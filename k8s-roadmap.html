00 · 사전 점검 — 컨테이너 기초

k8s는 "이미 컨테이너화된 앱을 어떻게 운영할 것인가"를 다루는 도구입니다. 아래가 이미 익숙하다면 바로 01단계로 넘어가세요.

image vs container Dockerfile docker build / run docker-compose 이미지 레지스트리
01

클러스터의 마인드 모델

2–3일

"컨테이너 하나 실행"이 아니라 "여러 컨테이너를 원하는 상태로 계속 유지시키는 시스템"이라는 관점으로 전환합니다.

핵심 개념
PodDeploymentReplicaSetNamespacekubectl선언적 YAML
프론트엔드 관점 Deployment는 package.json의 의존성 선언과 비슷합니다 — "이 상태여야 한다"를 선언하면 k8s가 실제 상태를 그쪽으로 계속 맞춰줍니다. npm이 노드모듈을 관리하듯, k8s는 컨테이너를 관리합니다.
실습

kubectl CLI를 설치하고, kubectl run으로 nginx Pod 하나를 띄운 뒤 kubectl get pods, kubectl describe pod, kubectl logs로 상태를 관찰해보세요. Pod를 지웠을 때 Deployment가 자동으로 새 Pod를 만드는 것도 확인합니다.

02

내 앱을 클러스터에 올리기

3–4일

로컬 클러스터를 띄우고, 빌드된 프론트엔드 정적 파일을 실제로 배포해봅니다.

핵심 개념
minikube / kindDeployment 스펙Service (ClusterIP)port-forward
프론트엔드 관점 npm run build 결과물을 nginx 베이스 이미지에 넣어 Docker 이미지로 만들고, 그 이미지를 Deployment로 배포합니다. 로컬 dev server 대신 nginx가 정적 파일을 서빙하는 구조로 바뀐다고 생각하면 됩니다.
실습

React/Vue 앱을 빌드 → nginx 기반 Dockerfile 작성 → 이미지 빌드 → minikube에 배포 → Service로 노출 → kubectl port-forward로 브라우저에서 확인.

03

설정과 트래픽

3–4일

환경별 설정 주입 방식과, 외부에서 들어오는 트래픽을 라우팅하는 방법을 익힙니다.

핵심 개념
ConfigMapSecretIngressService 타입 (NodePort/LB)
프론트엔드 관점 SPA는 이미 빌드 시점에 env가 번들에 박히는 경우가 많아, "런타임에 ConfigMap으로 env 주입"이 기대와 다르게 동작할 수 있습니다. 런타임에 값이 필요하면 entrypoint 스크립트가 컨테이너 시작 시 window.__ENV__ 같은 파일을 생성하는 패턴을 함께 봐두세요.
실습

ConfigMap으로 API 엔드포인트 값을 주입하고, Ingress로 /api는 백엔드 Service, /는 프론트엔드 Service로 라우팅되도록 구성합니다.

04

파이프라인 자동화

4–5일

YAML을 손으로 매번 적용하는 대신, 패키징하고 CI/CD로 자동 배포하는 흐름을 만듭니다.

핵심 개념
Helm이미지 태깅/레지스트리 푸시GitHub ActionsGitOps (ArgoCD)
프론트엔드 관점 Helm 차트는 "설정 가능한 npm 패키지"에 가깝습니다 — values.yaml로 환경별(dev/staging/prod) 오버라이드를 주는 구조가 .env.production과 비슷한 역할을 합니다.
실습

지금까지 만든 리소스를 Helm 차트로 묶고, GitHub Actions에서 이미지 빌드 → 레지스트리 푸시 → 차트 버전업까지 자동화해봅니다.

05

운영, 디버깅, 스케일링

3–4일

배포 후 "잘 떠 있는지, 문제가 생기면 어떻게 파악하는지"를 익힙니다.

핵심 개념
livenessProbereadinessProberesource requests/limitsHPAkubectl exec
프론트엔드 관점 Ingress 뒤에서 5xx가 뜨면 "브라우저 개발자도구"가 아니라 kubectl describe pod와 kubectl logs가 새로운 devtools입니다. probe 설정이 잘못되면 정상 동작 중인 Pod도 계속 재시작되니 가장 먼저 확인하는 습관을 들이세요.
실습

nginx에 헬스체크 경로를 추가하고 probe를 연결, resource limit을 낮게 잡아 OOMKilled를 직접 발생시켜본 뒤 로그로 원인을 추적합니다.

선택

더 깊이 (필요할 때)

지속적

프론트엔드 배포에는 필수가 아니지만, 조직 규모가 커지면 마주치는 주제들입니다.

핵심 개념
RBACNetworkPolicyService Mesh멀티 클러스터
